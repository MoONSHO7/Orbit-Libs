# Lua globals gate

## Description
Data for `../check-lua-globals.py`: the Retail and Forever client-name snapshot and this repository's allowances.

## Purpose
Reject, at edit and push time, the nil-global errors that otherwise reach BugSack: a function called above its `local`
definition, a missing module alias, a missing `local`, a misspelled or one-client API, a replaced client global. Orbit
owns the gate; the companion addons and Orbit-Libs carry byte-identical copies of the checker, snapshot and README.

## Implementation
- `WowGlobals.lua` is generated by Orbit's `.scripts/refresh-lua-globals.py` (`--check` reports staleness) from the
  workspace wow-ui-source `live` and `forever` branches: API documentation, globals Blizzard Lua and inline XML
  scripts or handlers set or read, XML frame names and `text=` keys, and the `C_*`, `Enum` and Lua-library fields
  Blizzard reads. Entries carry client bits (1 Retail, 2 Forever, 3 both); the file returns a function that builds one
  client's luacheck std. Never edit it; refresh it after a client update.
- `settings.json` belongs to its repository: `roots`, `exclude` (glob to reason), `ownedPrefixes` (globals the
  repository may set), `readGlobals` and `writableGlobals` (reason to names; `Name.field` extends an API table), and
  `missingOnRetail`/`missingOnForever` (names a guarded path references although that client lacks them).
- `check-lua-globals.py` fetches the pinned luacheck 1.2.0 release binary (SHA-256 checked) into `~/.cache/orbit-lint`
  (`LUACHECK` or `ORBIT_TOOL_CACHE` override it) and runs it once per client on codes 111-113, 121, 142 and 143. A
  finding on both clients fails; a one-client finding fails unless allowed; a stale allowance warns. An owned global
  set in any linted file, an XML `name=` or a literal `CreateFrame` name resolves in every file.
- Callers: Orbit's `lint.yml` job and `pre-push.py`; each companion's lint-only `.githooks/pre-push` (`--pre-push`
  exports every pushed commit); the workspace PostToolUse hook `.claude/hooks/check-lua-globals.py` and its Codex
  mirror, which pass the edited file. The workspace `.scripts/sync-lua-globals.py` copies the checker, snapshot,
  README and companion hook from Orbit (`--check` reports drift, `--install` sets `core.hooksPath`).

## Gotchas
- The gate cannot see guards: a call behind `if X then`, `Native.Require` or a client policy such as
  `SupportsEquipped()` still reports. Confirm the guard in both wow-ui-source branches, then list the name.
- A lowercase name enters the snapshot only when documented, defined at file scope, read through `_G` or a known
  builtin. Blizzard leaks locals such as `i`, `frame` and `questID` as globals; admitting them hides a missing `local`.
- wow-ui-source has no GlobalStrings.lua: a string Blizzard code or XML never names, or an undocumented C function
  such as `PlaySoundFile`, needs a `readGlobals` entry.
- Stale allowances only warn: commits from the shared tree land other agents' references separately, so an entry may
  serve a file that is not committed yet.
- Field writes on client tables (`SlashCmdList.X = f`, `frame.orbitKey = v`) are luacheck 122 and unchecked; only
  replacing a whole client global fails.
- A lint-only hook carries `orbit-pre-push: lint-only`, so the git guard still asks before agent pushes there. A
  commit without `settings.json` predates the gate and passes.
